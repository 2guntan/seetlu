# Decision log

| Date | Question | Decision | Why |
| --- | --- | --- | --- |
| 2026-11-20 | Edge hardware | Rockchip RK3588 (Orange Pi 5) + Frigate rknn detector; fallback Raspberry Pi 5 + AI HAT+ | Cheapest from China, Frigate supports the NPU natively |
| 2026-11-20 | Door counting method | Two band zones (`door_out`, `door_in`) and zone-sequence logic, not pixel line crossing | Frigate publishes zone changes reliably; positions are not streamed every frame |
| 2026-11-20 | Core health metric | Revenue per served customer vs the shop's own 14–28 day baseline | Works without per-sale cash logging; robust to shop size |
| 2026-11-20 | Video in the cloud | Only requested clips (≤ 20 s, 480p) and snapshots | Privacy, data cost, CDP regime |
| 2026-11-20 | M0: Python package management | `uv` with one `pyproject.toml` + `uv.lock` per Python package (`backend`, `edge/agent`, `edge/fake-frigate`) | Each package ships as its own image; uv is fast and gives reproducible locks |
| 2026-11-20 | M0: health endpoint not in 04-api | Add `GET /healthz` (ops only, no auth) on api, mock WhatsApp and fake-frigate | Needed for compose healthchecks and `make up --wait`; not a product feature |
| 2026-11-20 | M0: mock WhatsApp service | Separate `mock-whatsapp` compose service running `seetlu.messaging.mock_inbox` from the backend image; in-memory inbox at `GET /messages` | Simplest dev inbox; the `MessagingProvider` interface and persistence come in M7 |
| 2026-11-20 | M0: Android scaffold timing | `android/shop-phone/` is created in M9, not M0 | M0 "empty test per package" covers the packages the dev stack runs; Gradle/Android SDK in CI only when the app exists |
| 2026-11-20 | M0: edge agent in dev stack | The dev compose also runs `agent` (connected to `fake-frigate` via mosquitto) | Lets `make sim-day` drive the real agent later without a separate stack |
| 2026-11-20 | M0: edge image publishing | `edge-image.yml` builds amd64 + arm64 on PRs and pushes `ghcr.io/<owner>/seetlu-agent:<sha>` on `main` | Multi-arch build proven early; push only from main |
| 2026-11-20 | M0: MinIO image | MinIO removed its Docker Hub/quay images (Oct 2025) and archived upstream (2026). Dev uses `cgr.dev/chainguard/minio` pinned by digest; bucket created by `python -m seetlu.storage.init_bucket` (boto3) because the image has no shell | Keeps the locked S3/MinIO choice working in dev. **Open for M10:** production object store (patched MinIO build vs another S3-compatible store) needs an owner decision |
| 2026-11-20 | M1: how the first migration applies 03-data-model.sql | Copy the file verbatim to `backend/alembic/sql/0001-initial.sql` and run it with `exec_driver_sql`; a test fails if the copy drifts from `docs/03-data-model.sql` | The SQL stays the single source of truth; the copy is needed because the api image only contains `backend/` |
| 2026-11-20 | M1: downgrade of 0001 | Drop all tables and enum types; keep the `timescaledb` and `citext` extensions | Extensions are database-level and harmless; dropping timescaledb mid-session is fragile |
| 2026-11-20 | M1: UUIDv7 generator | Own RFC 9562 implementation in `seetlu.core.ids` (48-bit ms + 12-bit monotonic counter + random) | Python 3.12 has no `uuid.uuid7`; avoids a dependency; monotonic within a process |
| 2026-11-20 | M1: models vs schema | `tests/test_models.py` runs Alembic `compare_metadata` against the migrated DB and must return no diff (types, indexes, FKs, uniques) | Catches model drift automatically |
| 2026-11-20 | M1: token hashing | argon2id (`argon2-cffi`) for claim tokens, device tokens and OTP codes | Required by docs/09 for device tokens; one helper for all |
| 2026-11-20 | M1: seed scope | Seed skeleton now (account, 5 role users, 2 shops Dakar/Abidjan, 2 kits with door+counter cameras and zones, alert rules); 30 days of events and sales are added in M6 with the report engine | Seed data must match real engine outputs (2 worth_a_look, 1 large_gap, 1 missing-hours day) |
| 2026-11-20 | M1: backend DB tests | testcontainers (`timescale/timescaledb:2.17.2-pg16`), one container per session; each up/down test uses its own database | docs/10 test layer "API: pytest + testcontainers" |
| 2026-11-20 | M2: actions missing from the docs/09 matrix | Added `shop.view` (owner; manager/staff assigned; installer while installing; support), `shop.create` (owner, installer), `shop.settings` (owner; installer while installing), `audit.view` (owner, support), `support_grant.create` (owner) | Needed by 04 endpoints; each mirrors the closest matrix row; all in the exhaustive test |
| 2026-11-20 | M2: owner and `kit.command` | Owners cannot send kit commands (reboot/update); clip and snapshot go through `clip.view`/`snapshot.request` | Matrix row `kit.command` has owner ✗ |
| 2026-11-20 | M2: installer creating a shop | `POST /v1/shops` by an installer requires `owner {name, phone_e164}`; an unknown phone creates the account and owner user (receives_report=true) | Installers are not in an account; the owner must exist to receive reports |
| 2026-11-20 | M2: manager clip access toggle | `clip_access_for_managers` (account-level) is set through `PATCH /v1/shops/{id}` by the owner only | 08 puts the toggle in shop settings; 04 has no account endpoint |
| 2026-11-20 | M2: OTP rate limit storage | Rate limits (3 / 15 min per phone and per IP) count rows in `otp_codes` (new column `request_ip`); unknown phones also get a row (never sent) so 204/429 behave the same for any phone | No extra store; avoids phone enumeration |
| 2026-11-20 | M2: refresh tokens | `refresh_tokens` table (jti); rotation on every refresh; reuse of a rotated token revokes all of the user's refresh tokens | docs/09 "rotating, revocable" |
| 2026-11-20 | M2: MockProvider storage | `mock_messages` table (migration 0002); the `mock-whatsapp` service lists it at `GET /messages` | docs/07: MockProvider stores messages in `mock_messages`; one inbox for API, worker and tests |
| 2026-11-20 | M2: edge config version | Changing timezone, opening hours, expected staff or service/wait/unattended thresholds bumps `config_version` of the shop's kits | Agents poll config with ETag = config_version (M3) |
| 2026-11-20 | M2: hidden vs forbidden | A shop the user cannot see returns 404; a visible shop with a disallowed action returns 403 | Does not reveal other accounts' shop ids |
| 2026-11-20 | M3: device token lookup | Device token = `<kit id>.<32 random bytes>`; only the secret part is stored (argon2id) | The kit row is found by id without scanning hashes; still hashed at rest per docs/09 |
| 2026-11-20 | M3: register preconditions | `POST /v1/edge/register` needs the right claim token and a kit attached to a shop (status not `in_stock`/`retired`); every call rotates the device token | 04: "only after installer claim"; 09: rotate on re-registration |
| 2026-11-20 | M3: config ETag | `ETag: "<kits.config_version>"`; `If-None-Match` match → 304 | config_version is bumped by every zone/camera/threshold change |
| 2026-11-20 | M3: `target_agent_version` null | Omitted from `EdgeConfig` when unset | 04 types it as string; the contract test caught it |
| 2026-11-20 | M3: zone geometry storage | `zones.geometry` stores the 04 shape directly: a list of `[x, y]` normalised points (2 points for `door_line`) | Same shape in DB, API and agent; no conversion |
| 2026-11-20 | M3: event upsert semantics | `INSERT … ON CONFLICT (id, started_at) DO UPDATE` of `is_staff`, `ended_at`, `confidence`, `frigate_event_ids`, `meta`; response counts inserts as `accepted` and conflicts as `duplicates` | Idempotent retries + the staff correction (AC-F1-3) use the same id |
| 2026-11-20 | M3: unknown camera name in an event | Stored with `camera_id` NULL and `meta.camera` = the name | Never drop events (docs/05) |
| 2026-11-20 | M3: command delivery | `GET /v1/edge/commands` returns `queued` and `sent` unexpired commands (marks them `sent`); expired ones become `expired`; results are idempotent | Survives agent crashes between poll and result; agent dedupes by command id |
| 2026-11-20 | M3: clip object keys | Server chooses `shops/<shop>/clips|snapshots/<command id>.mp4|jpg`; a key reported by the agent is ignored; clip rows expire after 7 days | An edge box cannot point a clip row at another object; docs/09 rule 4 |
| 2026-11-20 | M3: presigned URLs in tests | Signed offline with boto3 and checked for key, signature and 600 s expiry; real upload to MinIO is exercised by the agent integration tests (M5) | Avoids a MinIO testcontainer (no maintained image with a shell) |
